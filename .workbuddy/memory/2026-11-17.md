## ZCode 供应商切换功能（feat 539165c5b）

- 背景：ZCode app 的模型选择器能切供应商（Start Plan / AI Switch），YoYoCode 里 zcode 智能体只有扁平模型列表。核实上游 zcode-acp 源码（clone 到 `~/.zcode/tmp/zcode-acp-upstream`）后确认：供应商是进程级 bootstrap 变量（`ZCODE_PROVIDER`，故意不可文件配置），ACP 无 provider 维度。
- 落地：设置 → ZCode 加供应商下拉（写 env_json 的 `ZCODE_PROVIDER`，与 env 文本框同一 Save）；后端 `acp_zcode_list_providers` 双模式命令镜像桥接扫描规则（`~/.zcode/v2/config.json` + `acp-accounts.json` 叠加 + `providerSelectable`），只出 id/名称/可用性不出密钥；`agent_env_keys` 给 ZCode 显式条目（占位符避开 `ZCODE_BASE_URL` —— 它是 app-server service origin，桥接会剥离），`keeps_own_providers` 收编 ZCode。
- 关键事实：本机 `~/.zcode/v2/config.json` 里 `builtin:bigmodel-start-plan` 是 disabled/keyless，账号套餐（Start Plan OAuth）模型在 headless 桥接下不可见；serde camelCase 会把 `base_url` 拼成 `baseUrl` 而 config.json 写的是 `baseURL`，需显式 rename（单测抓过）。已提上游 issue william0wang/zcode-acp#400。

## 修复：桌面版本号机制检测不到更新（同日追加）

- 根因：safe 模式（原默认）只把 plus 迭代号放 git tag/release 标题，不写 version；桌面 tauri-plugin-updater 默认比较 `release.version > current_version`，semver 里 `0.44.0-plus.N < 0.44.0`。实测线上 `latest.json` version 恒为纯三段 `0.44.0` → plus.1~4 桌面用户一次都没收到更新提示。server 侧 `update/version.rs::is_newer()` 自带 plus 排序测试，本来正常。
- 修复（用户选「存量用户手动重装一次」方案）：身份注入默认版本模式 `safe → semver`，`tauri.conf.json` / package version 写成 `x.y.z-plus.N`；safe 保留为 `--version-mode safe` 逃生舱。改了 4 文件：`scripts/apply-plus-identity.mjs`、`release.yml`（两处注入显式 `--version-mode semver` + tag 校验注释）、`docs/PLUS-PATCHES.md`（版本模式段重写）、`scripts/server-release.test.mjs`（桌面版本回归测试 + safe 逃生舱 + CI 步骤断言）。
- 关键警告：存量 plus.1~4 装的都是纯三段 `0.44.0`，新版 `0.44.0-plus.N` 按 semver 反而更小，仍收不到自动更新——需手动装一次首个 semver 版，之后迭代恢复。已写入 PLUS-PATCHES.md。
