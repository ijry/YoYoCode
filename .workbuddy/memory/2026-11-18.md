## 流式本地 ASR PoC（sherpa-onnx）

- 用户问「引入 ONNX Runtime 复杂吗」，确认要 PoC。新增独立 crate `tools/voice-stream-poc`（`[workspace]` 隔离，不进 `src-tauri` 构建图），依赖 `sherpa-onnx = "2.0.1"`，用 `OnlineRecognizer` + `OnlineStream` 做流式识别，不改现有 `voice.rs`。
- 模型：`sherpa-onnx-streaming-zipformer-zh-14M-2023-02-23` int8；encoder 20.6MB + decoder 1.8MB + joiner 1.7MB + tokens ≈ 24.2MB。GitHub 直连下载慢（74MB 约 20KB/s），改用 `gh-proxy.org` + `--ssl-no-revoke` 约 32s 下完；HF 直连被代理 502。
- 构建：`sherpa-onnx` 2.x 默认静态链接，构建脚本自动下 native 库；本机预下 `sherpa-onnx-v2.0.1-win-x64-static-MT-Release-lib.tar.bz2`（117MB）并用 `SHERPA_ONNX_ARCHIVE_DIR` 指向 `.cache`，release 编译 2m25s；可执行文件 17.8MB。
- 实测（Windows x64，CPU，2 线程，100ms 分块）：5.61s 中文音频首 partial 730ms，decode 212ms，RTF 0.038；`--fast` 首 partial 27ms、decode 191ms、RTF 0.034；160ms 分块首 partial 661ms、RTF 0.030。两段官方 test_wavs 输出通顺；模型加载 1.4–1.7s，产品需在 composer 挂载/首次聚焦时预加载，不能等首次点麦克风。
- 结论：sherpa-onnx Rust crate 接入成本低（API 几十行），真正的成本在流式会话/前端 PCM 分块/多语言模型分发；14M 中文模型 24MB、RTF 0.03、首字 ~0.7s，作为中英流式引擎可行，其他语言仍回退 whisper 批式。PoC 文件：`tools/voice-stream-poc/{Cargo.toml,src/main.rs,README.md,.gitignore}`；模型/target/.cache 已 ignore。
