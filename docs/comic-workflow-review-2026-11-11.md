# 漫剧工作流审查：完善程度、易用性、执行闭环与双视图

- 审查日期：2026-11-11
- 代码基线：`f625b4d0b`
- 审查对象：项目内的漫剧制作工作台、会话/MCP 桥接、媒体任务、供应商设置、导出与部署。
- 性质：代码审查与公开产品资料比较，不是实机全面验收，也不构成实施、付费生成或发布授权。
- 相关文档：[使用指南](comic-production-guide.md)、[此前流程修复计划](comic-workflow-repair-plan.md)。

## 1. 总体结论

**当前已有较完整的“会话驱动制作工作台”，但还不是用户可独立操作、可靠恢复的可视化工作流引擎。**

已有项目、分集、剧本、分镜、资源卡、媒体任务、候选审核和合成的业务骨架。手工编辑与智能体创作使用同一份 `story/` 文件，桌面、服务器和 MCP 大部分业务复用同一 core，这些基础值得保留。

最影响实际使用的不是缺少节点连线，而是以下问题：

1. 后台任务和前端编辑存在旧快照覆盖，可能撤销已保存内容或已绑定素材。
2. 部分部署和素材组合无法走完生成到成片的闭环。
3. 生成按钮实际排队的是会话指令，界面尚未完整表达“排队指令、创建制作任务、生成、审核、绑定”的不同状态。
4. 资源新建、任务历史、逐镜重试/取消、预算控制等操作仍不完整。
5. 普通视图与画布视图有可复用的技术基础，但没有现成的漫剧双视图或依赖调度层。

**建议先解决数据一致性与制作闭环，再做共享数据的分集级普通/画布切换。第一版画布应展示和操作现有制作状态，不应把视觉连线直接包装成已具备执行语义的工作流。**

本文不使用主观总分替代验收。下表区分已具备的能力与投入实际制作前的差距。

| 维度 | 已具备 | 主要差距 |
| --- | --- | --- |
| 制作模型 | 项目、分集、剧本、分镜、角色/场景/道具 | 上游变化后的素材失效提示、制作版本与依赖追踪 |
| 创作入口 | 初始化向导、会话整理、分镜生成、手工编辑 | 新建资源没有直接表单，生成依赖当前会话能力 |
| 候选审核 | 图片选用、音频绑定、视频预览与确认 | 完整历史、镜头级版本对比、配音试听与明确审核状态 |
| 执行可靠性 | 任务记录、远端 handle、取消状态保护 | 并发写竞争、局部队列阻塞、恢复前读取已上传参考图 |
| 导出 | 显式合成、本地打开/Web 下载 | 无图的纯视频镜头被阻断，容器依赖缺失 |
| 易用性 | 分集管理、草稿恢复、确认操作、下一步提示 | 队列语义、加载失败恢复、素材创建与批量操作 |
| 可视化 | 项目已有 React Flow 画布基础 | 当前没有漫剧节点、业务连线或双视图共享状态 |
| 验证 | 前后端专项、媒体检测与合成测试 | 缺少真实 UI 到后端闭环、付费供应商和部署验收 |

## 2. 实际操作链路

工作台明确定位为观察和编辑项目 `story/` 的界面。生成由会话驱动，机械编辑则直接写入业务 API，见 [工作台定位](../src/components/comic/comic-workbench-panel.tsx#L94)。

| 步骤 | 直接通过工作台完成 | 需要智能体或其他入口 |
| --- | --- | --- |
| 初始化 | 填剧名、选择原创/小说来源、初始化及导入 | 可以让智能体执行同一套 MCP 操作 |
| 创建分集与剧本 | 新建集、改标题、粘贴并保存剧本 | 原创/改编、整理既有会话成果由智能体落盘 |
| 准备资源 | 编辑已有卡片，上传参考图及角色三视图 | 新建角色/场景/道具依赖 MCP 或文件操作 |
| 分镜 | 手工添加、编辑、排序、删除，高级 JSON 导入 | “从本集剧本生成分镜”排队会话指令 |
| 图片/视频/配音 | 审核结果，绑定图片/音频，预览并确认视频 | 生成按钮由智能体随后创建和轮询制作任务 |
| 合成与取件 | 成功后本地打开或 Web/远程下载 | 合成按钮先排队会话指令，由智能体调用合成工具 |

生成链路为：工作台 `send()` → `requestComicConversationTask()` → 当前 tab 的待发送指令 → 会话队列 → 智能体实际调用制作工具。见 [动作目标与发送](../src/components/comic/comic-workbench-panel.tsx#L383)、[会话桥接](../src/lib/comic-session-bridge.ts#L22)、[队列接收](../src/components/conversations/conversation-detail-panel.tsx#L1860)。

因此：

- “指令已排队”不等于已创建生成任务，更不等于供应商正在生成。
- 忙碌会话仍可接收排队指令；连接未就绪时会等待发送。
- 没有同项目会话时 AI 动作不可用；Pi、Cline、OpenClaw 明确走手工模式。
- 其他代理的按钮可用，也不等于已验证该会话真的具备漫剧 MCP 能力。
- 列表与画布切换必须保持同一项目、分集和生成目标，不能悄悄新建另一个会话。

## 3. 缺陷与风险

### 3.1 优先级与证据口径

- **P1：高优先级。** 可能丢失已保存状态，或在支持的运行环境中阻断主要制作链路。
- **P2：中优先级。** 条件性闭环问题、配置问题、任务可管理性或使用体验问题。
- 本轮没有确认需要按全局灾难级处理的 P0；以下优先级按影响范围与触发条件统一标记。

除另有说明外，发现基于实际代码链路确认，未在真实浏览器、供应商或容器环境端到端复现。缺少测试不等于问题不存在，现有专项通过也不覆盖下述全部场景。

### R01 · P1：后台分镜读改写不在同一锁内

- **触发：** 同集多个镜头生成完成，或生成完成/选图与用户编辑、绑定音频、排序并发。
- **原因：** `mark_candidate` 和 `bind_candidate` 在锁外读取整份 storyboard，随后才通过 `write_storyboard` 取得锁并整份写回；写回只合并最新 `video`，不保护其他字段。
- **影响：** 后写入的旧快照可能撤销先写入的台词、图片、音频或顺序，两条操作仍返回成功。文件原子替换不等于读改写业务事务原子化。
- **证据：** [task.rs:843](../src-tauri/src/comic/task.rs#L843)、[task.rs:1066](../src-tauri/src/comic/task.rs#L1066)、[store.rs:389](../src-tauri/src/comic/store.rs#L389)、[store.rs:407](../src-tauri/src/comic/store.rs#L407)。
- **建议与验收：** 在同一项目锁下读取最新内容并执行字段级业务变更。并发更新不同镜头、不同素材绑定时都不丢失；同字段竞争须有明确冲突或覆盖规则。

### R02 · P1：分镜编辑保存会提交旧素材绑定

- **触发：** 打开镜头编辑框后，智能体或另一客户端更新镜头或绑定首帧、配音，再保存原编辑框。
- **原因：** 编辑稿保存打开时的 `StoryShot`，提交旧 `state`、`selected`、`audio`；后端替换同 ID 镜头。只有视频绑定有专门保留逻辑。
- **影响：** 普通文本编辑可能回滚新确认的图片、配音或状态。
- **证据：** [编辑快照](../src/components/comic/comic-workbench-panel.tsx#L755)、[保存字段](../src/components/comic/comic-workbench-panel.tsx#L1438)、[镜头替换](../src-tauri/src/comic/store.rs#L559)。
- **建议与验收：** 普通编辑采用字段级补丁或带版本的条件更新，素材绑定走独立操作；不要用无条件整对象提交覆盖服务器最新绑定。显式整集导入仍应保留自身的确认与替换语义。

### R03 · P1：保存角色卡遗漏固定种子

- **触发：** 角色已配置 `seed`，用户修改名称、描述或提示词并保存。
- **原因：** 前端提交对象遗漏 `seed`，Rust 默认反序列化为 `None`，随后整份覆盖角色卡。
- **影响：** 已配置的固定种子丢失，后续提示词组装改用其他种子来源，损害原有生成一致性设置。
- **证据：** [保存对象](../src/components/comic/comic-workbench-panel.tsx#L1802)、[CharacterCard](../src-tauri/src/comic/model.rs#L334)、[写入](../src-tauri/src/comic/store.rs#L883)、[种子选择](../src-tauri/src/comic/prompt.rs#L157)。
- **建议与验收：** 明确区分字段省略与显式清空，保存文本不改变种子；添加含种子的角色编辑回归。固定种子只是现有一致性机制之一，不应被宣传为保证所有模型的角色一致性。

### R04 · P1：资源面板保存会覆盖后台更新的参考素材

- **触发：** 资源面板打开后，智能体或另一客户端更新卡片参考图、服装或三视图，用户随后保存一个文本字段。
- **原因：** 卡片只按资源身份加载，不订阅资源变更；保存携带旧 `refs`，角色还携带旧 `turnaround`、`outfits`、`expressions`，后端没有版本比较。
- **影响：** 后台刚更新的参考素材被旧快照替换。
- **证据：** [加载](../src/components/comic/comic-workbench-panel.tsx#L1770)、[保存](../src/components/comic/comic-workbench-panel.tsx#L1798)、[整份写入](../src-tauri/src/comic/store.rs#L883)。
- **建议与验收：** 资源文本编辑与素材维护拆分或带版本校验；事件刷新不覆盖本地草稿，保存旧草稿不会撤销新参考图。

### R05 · P1（缺依赖环境）：容器音视频链路缺少运行依赖

- **触发：** 使用仓库标准或发布 Docker 镜像，且未自行安装 FFmpeg/FFprobe。
- **原因：** 两份 Dockerfile 均未安装这两个工具；媒体验收与合成直接通过 PATH 启动程序。
- **影响：** 音视频供应商可能已返回收费结果，任务才因本地验收失败而终止；整集合成也无法完成。
- **证据：** [Dockerfile](../Dockerfile#L26)、[Dockerfile.ci](../Dockerfile.ci#L7)、[音频检测](../src-tauri/src/comic/audio.rs#L74)、[视频检测](../src-tauri/src/comic/video.rs#L72)、[合成进程](../src-tauri/src/comic/compose.rs#L618)。
- **建议与验收：** 镜像安装依赖，并在媒体提交前进行能力预检；缺依赖时明确提示，不应先收费后失败。本地已安装工具的环境不受该缺陷影响。本轮未运行 Docker 实机验证。

### 3.3 额外观测：短视频与合成目标时长

只使用本地 FFmpeg 内存管道生成 0.5 秒、24fps 视频，再按现有视频分支的缩放/裁切/帧率、静音填充和 `-t 2.0` 处理，FFprobe 返回：

| 对象 | 时长 |
| --- | --- |
| 视频流 | 0.500000 秒 |
| 音频流 | 2.083333 秒 |
| 容器 | 2.083333 秒 |

这证明当前参数组合没有实际补齐视频帧，而只延长了音频/容器时长。现有合成测试主要检查容器时长和可解码性，见 [视频分支](../src-tauri/src/comic/compose.rs#L424)、[测试](../src-tauri/src/comic/compose.rs#L893)。

**这不是完整播放器或多镜头拼接验收，不能据此宣称必然黑屏、错位。** 建议补测视频帧时长、音频时长及跨镜头边界，并明确短片段采用保持末帧、循环、裁切还是调整镜头时长。

## 4. 产品完整度与友好性改进

以下是产品能力建议，不与已确认代码缺陷混为一谈。

### 4.1 面向普通创作者的闭环

- 增加角色/场景/道具新建表单及服装编辑；资源面板不能只显示已有卡片。
- 把“待发送指令、智能体处理中、已创建媒体任务、供应商运行中、待审核、已绑定、失败”明确区分。
- 生成不可用时说明具体原因，并提供回到同项目会话、检查工具或采用手工操作的入口。
- 供应商设置提供有效的连通性/能力检查；真实收费试跑必须单独说明费用并经确认。现有 `testMediaProvider` 只检查配置形状，不能称为验证真实生成可用。
- 失败不清空已有结果；展示失败原因、是否已收费、是否可恢复、重试使用的输入版本。

### 4.2 素材审核和批量制作

- 按镜头保留候选历史、当前选用版本及来源任务；最近任务摘要不是完整素材库。
- 支持图片放大对比、配音试听、视频 take 切换；更换候选不删除历史。
- 增加多选镜头、批量生成范围、逐镜重试/取消与失败筛选。
- 视频/音频/图片分别审核，不能将“生成成功”等同于“用户已确认可用于导出”。
- 补充可撤销的机械编辑；撤销付费外部动作不能伪装成取消收费，应明确边界。

### 4.3 预算、来源与权限

- 硬预算和付费批次确认不能只依赖提示词“超预算先问”。批准应对应具体供应商、镜头范围、模型、数量及输入版本。
- 提供预估时标明估算依据；供应商不提供价格时显示未知，而非虚构准确成本。
- 区分智能体会话成本和媒体供应商成本，记录可获得的实际用量。
- 记录分镜使用的角色/服装/场景/参考图版本；上游改变后提示下游结果可能过期，但不自动删除或收费重生成。
- 对小说、上传素材、声音和生成视频提供来源记录及发布前权利确认位置；本轮没有审查具体素材授权或服务条款。

### 4.4 文档与入口

已有首页、输入框、左侧导航、辅助面板等入口，使用指南应补齐入口与“无活动项目”的处理。改进设置提示、错误恢复和手工模式说明，避免用户将“已写入聊天”误认成“已保存到工作台”。

## 6. 普通界面与画布切换的可行性

### 6.1 现有基础与复用边界

**技术上可行，当前尚未实现。**

项目已引入 `@xyflow/react`。通用画布具有拖拽、缩放、框选、多选、MiniMap、卡片尺寸和视口恢复。可参考 [React Flow 挂载](../src/components/canvas/canvas-view.tsx#L2184)、[布局工具](../src/components/canvas/canvas-model.ts#L331)、[卡片框架](../src/components/canvas/nodes/card-frame.tsx#L24)、[视口存储](../src/lib/canvas-view-storage.ts#L164)。

但：

- 现有画布的 `edges={[]}`，不是已实现的节点连线流程。
- 节点主要是会话、区域、便签、文件与终端，见 [节点注册](../src/components/canvas/canvas-view.tsx#L141)。
- 整体画布耦合会话、终端、ACP 和全局工作台，不能简单整体搬入漫剧模块。
- 普通漫剧视图的 `shots/script/tasks` 在 `StoryboardPanel` 内部，store 主要共享 overview、选择和草稿，见 [面板状态](../src/components/comic/comic-workbench-panel.tsx#L740)。
- 普通视图生成操作依赖当前 tab，而画布会话使用独立连接上下文。第一版不应为每个漫剧节点挂一套聊天或 ACP 连接。

### 6.2 三个层次不要混淆

1. **状态可视化：** 展示现有剧本、分镜、资源和任务，连线表达引用或制作阶段。
2. **可操作双视图：** 节点和普通表单调用相同编辑、审核、绑定与生成入口。
3. **可执行流程编排：** 连线决定依赖、输入输出、排队、失败传播、恢复与下游重跑。

前两层可在现有模型上渐进完成。第三层需要明确的执行模型，当前逐任务生成、显式绑定和显式合成并不自动具备这些能力。`refs` 说明素材引用，不足以直接生成可调度 DAG。

### 6.3 方案比较

| 方案 | 内容 | 成本与风险 | 建议 |
| --- | --- | --- | --- |
| A：分集级可操作双视图 | 在同一个漫剧工作台内切换普通/画布；共用状态和命令 | 需要上提面板状态、统一刷新与草稿、设计漫剧节点；边界最清楚 | **推荐目标** |
| B：挂入现有全局画布 | 将漫剧作为全局画布新节点类型，跨会话展示 | 目标身份、路由、ACP 生命周期及全局模型耦合较多 | 不作为第一版 |
| C：分集级只读状态图 | 展示素材引用、任务与待审核状态，点击回到普通编辑 | 范围最小，可先验证画布是否帮助查找阻塞与候选 | **推荐前置里程碑** |

推荐顺序是 C → A，不是用只读图冒充完整工作流编辑器。用户尚未批准具体双视图实现；本节是供后续设计选择的建议。

### 6.4 推荐的双视图行为

- 工作台顶部提供“普通 / 画布”切换，项目和分集选择保持不变。普通视图默认保留，窄屏优先普通视图。
- 画布按集组织：剧本、分镜组、镜头卡、角色/场景/道具引用、图片候选、视频/配音、导出结果。
- 镜头顺序、资源引用、制作步骤依赖必须有不同的视觉标识；不要用一种箭头混合表达。
- 节点展示缩略图、状态、输入来源和当前选用结果；完整字段与媒体预览使用共用编辑器/侧面板，避免所有节点同时播放视频。
- 切换视图不自动发送会话指令、不生成、不绑定素材、不触发收费。
- 生成仍使用明确的同项目目标；“指令排队”和“制作任务排队”分别反馈。
- 未保存草稿、候选选择和失败信息在切换后保留；拖动位置和视口只改变布局，不改变分镜顺序或业务状态。
- 画布模式、视口和节点位置属于布局偏好，与业务数据分离；具体存储位置在实施设计时确定。
- 使用 `folderId + episodeId + shotId/taskId` 等稳定身份，禁止按数组索引关联素材。
- 保留键盘操作、可读状态文字、非颜色单一提示及回到普通视图的入口。

### 6.5 数据与操作边界

建议保留 `story/` 内容及任务数据库作为现有业务真源，增加共享查询缓存和动作层，不为画布维护第二份剧本、分镜或候选内容。

1. 将分集读取、任务读取、事件订阅、加载/错误状态从单一视图上提。
2. 对每个项目/分集处理最新请求与过期响应，避免重复订阅和旧结果回写。
3. 草稿与服务器快照分离，冲突显示由普通/画布视图共用。
4. 文本编辑、素材绑定、视频审核、排序、显式导入分别定义业务操作，复用原子更新和版本检查。
5. 第一版连线从现有顺序、引用和任务关系派生，不开放任意连线执行。
6. 若未来支持自由编排，再定义节点输入/输出类型、循环校验、执行快照、依赖失效、幂等、人工审批与恢复语义；不能只增加 React Flow 的 `onConnect`。

## 7. 建议实施顺序

本节是改进路线，不是已批准的实施计划；不提供未经测算的工期。

### 阶段一：数据安全与基本闭环

- 修复 R01–R04，保留显式导入与视频审核的现有保护。
- 补齐容器媒体依赖及提交前能力预检。
- 修复模型列表契约和纯视频合成路径。
- 为并发、旧草稿、同路径图片替换和真实请求解析增加回归。

**完成标志：** 正常机械编辑与后台生成互不撤销，支持的媒体组合可导出，错误发生在可解释的步骤且不会无意重复收费。

### 阶段二：无需猜测的制作操作

- 增加资源新建、任务历史与镜头级候选入口。
- 补齐失败/重试/取消、有效供应商检查和执行状态反馈。
- 改善恢复、调度公平性、默认供应商唯一性与未注册目录处理。
- 批量动作显示作用范围；收费确认与实际提交参数绑定。

**完成标志：** 普通用户知道当前等待什么、失败在哪里、如何恢复，较早候选不会因摘要截断而不可操作。

### 阶段三：共享数据与只读画布

- 上提分集、任务和错误状态，普通界面行为保持不变。
- 交付方案 C，验证用户能否更快定位缺素材、待审核和依赖引用。
- 覆盖切集、切视图、草稿保留、视口恢复和低性能设备的基本行为。

**完成标志：** 图与普通界面始终展示同一份状态，切换不改变内容或发起制作动作。

### 阶段四：可操作双视图

- 交付方案 A，共用编辑、候选选择、审核和现有生成入口。
- 增加镜头分组、搜索/筛选与有范围提示的批量操作。
- 独立评估是否真的需要自由节点编排；若需要，另行确认执行模型与设计。

**完成标志：** 用户可在两种视图完成相同核心动作，不需要迁移或同步第二套项目。
