# YoYoCode v0.44.0-plus.5

## 本版范围

基于上游 Codeg 0.44.0 的第五个 PLUS 迭代，包含自 `v0.44.0-plus.4` 以来的改动。**本版修复桌面端检测不到更新，并首次切换到 semver 版本模式**：安装包内部应用版本与 `latest.json` 都带迭代号（本版为 `0.44.0-plus.5`），不再只是 tag / Release 标题承载。

## 修复：桌面版本号机制检测不到更新

- **根因**：此前默认的 safe 模式把 plus 迭代号只写在 git tag 与 Release 标题，`tauri.conf.json` 的 `version` 恒为纯三段 `0.44.0`。桌面端 `tauri-plugin-updater` 用 `release.version > current_version` 判断更新，而线上 `latest.json` 的版本也是 `0.44.0`——两端永远相等，桌面端一直报告「已是最新」。加上 semver 里 `0.44.0-plus.N < 0.44.0`，即便把迭代号写进清单也仍被判为更旧。结果是 plus.1 到 plus.4 的桌面用户一次都没收到过更新提示。
- **修复**：身份注入默认版本模式改为 semver，`tauri.conf.json` / `package.json` 的 `version` 写成 `x.y.z-plus.N`；`latest.json` 与更新包签名随之带迭代号，`plus.4 → plus.5` 能被正确识别为更新。排序由 semver 处理，Server 侧 `update/version.rs` 早有对应测试覆盖。原来的 safe 模式保留为 `--version-mode safe` 逃生舱，仅在 semver 打包真出问题时临时回退。
- Windows 此前保留 safe 的理由是 MSI 的 ProductVersion 不接受 prerelease 段；但 MSI 早已因 tauri#14681 在流水线中跳过（Windows 只打 NSIS + updater），这条顾虑已随 MSI 一起消失。

## 升级路径与已知限制

- **存量用户需手动装一次本版**：plus.1 ~ plus.4 装到机器上的都是纯三段 `0.44.0`。按 semver，`0.44.0-plus.5` 反而比它「小」，这些用户的自动更新仍不会提示本版，需到 Release 页手动下载安装一次。**从本版（首个 semver 版）起，后续迭代（plus.6 及以后）恢复自动检测。** 这与 plus.1 / plus.2 因 server 改名需手动重装是同类的一次性迁移成本。
- plus.4 → plus.5 的自动更新在存量 pure-`0.44.0` 安装上不会触发，属预期行为，非回归。
- 其余沿用 plus.4 说明：默认端口 **18989**；MCode 连接配置码包含访问令牌，请勿分享；macOS 安装包沿用 ad-hoc 签名，不做 Apple 公证。

## 验证与已知限制

- 发布脚本回归测试 `node --test scripts/server-release.test.mjs scripts/server-install-download.test.mjs`：14/14 通过（含桌面 semver 版本回归、safe 逃生舱、CI 步骤断言）。
- 身份注入 `--check` 实测：默认输出 `0.44.0 → 0.44.0-plus.5`，`--version-mode safe` 仍输出纯三段 `0.44.0`。
- 静态核查：tag `v0.44.0-plus.5` 通过校验正则；注入后 `CODEG_APP_VERSION`（前端）、server `/health` 版本、service worker 缓存 key 均随 plus 号一致变化；tag 含 `-` 触发 RPM 跳过逻辑。
- 本版是 semver 模式首次发版，tauri-action 打包带 prerelease 版本号的产物为首次经 CI 验证；桌面 installer 生成与 updater 签名以 CI 结果为准。
- 本轮仅改动发版脚本 / CI / 文档 / 测试，未触碰 Rust 与前端业务代码，故未重跑 cargo / vitest 全量；相关基线状态沿用 plus.4（桌面测试 exe 的本机 `STATUS_ENTRYPOINT_NOT_FOUND` 为既有环境问题）。
