# YoYoCode v0.45.0-plus.3

新增完全本地的语音输入：说话即出字的流式转写（中英文）与「录完再转」的通用兜底，并把 ZCode 会话内供应商切换升级为读取桥接元数据的普通模型切换。

## 本地语音输入（双引擎）

- 输入框新增麦克风按钮，两种引擎共用一套交互：浏览器自带识别（Chrome/Edge 的 Web Speech，零下载、远控窗口也可用）与本地识别（16 kHz PCM 本地采集，whisper.cpp 解码，音频不出本机）。
- 本地引擎首次使用自动在应用内下载解码器与模型（约 150 MB），进度实时可见，无需终端命令；macOS 无预编译解码器时明确提示 `brew install whisper-cpp` 安装指引。
- 转写文本插入输入框供审阅后手动发送，绝不自动发出。

## 中英流式实时转写

- 界面语言为中文或英文时，本地引擎自动升级为流式识别：基于 sherpa-onnx 14M 流式 Zipformer（int8 约 24 MB，CPU 实时率约 0.03），说话过程麦克风旁实时显示部分转写，停麦后完整文本落入输入框。
- 其余界面语言保持「录完再转」的 whisper 路径；两种模型首次使用均自动下载（流式模型约 75 MB），模型加载约 1.5 秒由输入框挂载时预热，点击麦克风即时开始。
- 引擎可在浏览器识别与本地识别间随时切换；本机解码，无任何第三方上传。

## ZCode 会话内供应商切换（改进）

- 会话内 ZCode 供应商页签改读桥接 `_meta.zcode` 元数据（zcode-acp 0.88.0 起）：切换供应商就是一次普通模型切换（`providerId\defaultModel`），不再写入 agent 环境变量重连；供应商列表随凭证变更实时刷新。
- 内置桥接 pin 由 0.85.2 升至 0.88.1（含 #404 修复）。
- 不向后兼容：桥接低于 0.88.0 时不再显示会话内供应商页签，也没有磁盘扫描兜底；连接前固定供应商仍走设置页。

## 升级说明

- 延续完整版本号机制，构建产物及更新清单使用 `0.45.0-plus.3`，已安装 `0.45.0-plus.2` 的用户在本版正式发布后可使用内置更新。
- 仓库内上游版本基线仍为 `0.45.0`，PLUS 版本号、品牌和更新源由构建时注入，无新增数据库迁移。
- 默认 Web 服务端口仍为 **18989**；MCode 连接配置码包含访问令牌，请勿公开分享。
- macOS 安装包仍采用 ad-hoc 签名，尚无 Apple Developer ID 公证；服务器包继续提供 Linux x64、Linux arm64、Windows x64。
- 语音模型与解码器下载源为 GitHub / Hugging Face；受限网络环境可通过 `CODEG_WHISPER_BIN` / `CODEG_WHISPER_MODEL` / `CODEG_STREAM_MODEL_DIR` 环境变量指向本地已备好的文件。

## 验证

- 引擎级端到端：真实 14M 流式模型与官方测试音频走生产同款 prepare → start → 100 ms 分块 → stop 链路，增量部分转写与最终文本断言通过（本机实测通过，模型缺失环境自动跳过）。
- Rust：voice / voice_stream 单测 **12/12**；桌面 `cargo check`、server-bin `cargo check` 均通过；clippy（桌面 `--all-targets --features test-utils` 与服务器 lib）零警告。
- 前端：vitest 全量通过（含 voice-input **13/13**、message-input **129/129**、安装下载回归 **46/46**）；TypeScript 全量无输出类型检查通过。
- 版本注入预检：桌面与服务器模式均确认 `0.45.0 → 0.45.0-plus.3`。
- CI：release/test 工作流为 sherpa-onnx 原生库增加按 target 的构建缓存，避免每个 job 重复下载约 120 MB。
