# YoYoCode v0.49.0-plus.2

基于 Codeg 0.49.0，修复轮次上限恢复漏触发，并完善「在新会话中继续」的队列与状态继承。

## 本次变化

- **轮次上限恢复**：修复代理将 `session_turn_limit_exceeded` 作为会话失败事件上报、同时正常返回 `end_turn` 时，未触发已配置的压缩或新会话恢复的问题。兼容嵌套 JSON、JSON 字符串及准确的中英文提示，避免将普通 `/compact` 建议误判为上限。
- **新会话携带消息队列**：手动续接和轮次上限自动续接都会复制待发送内容、附件引用、顺序、定时时间、发送模式及单条暂停状态；草稿保存、恢复和 Chat 续接也保留来源。
- **继承会话选择**：同一智能体续接时沿用原会话的模型、模式和配置，显式选择的新配置优先；切换智能体时不复用不兼容配置。
- **避免重复发送**：会话与队列状态在同一数据库事务中创建；旧队列保留但暂停，新队列在首次续接消息成功前不自动派发。原有手动或错误暂停继续保持暂停；已发送、已移除的项目不会复制，发送结果不明确的项目需人工确认，不自动重发。
- **Chat 独立目录**：自动续接 Chat 时为新会话创建独立的隐藏文件夹和临时工作目录，不复用旧会话的执行身份。
- **队列操作**：包含上一版之后提交的单条消息暂停，以及输入框菜单中的队列控制入口。

## 升级说明

- 构建产物与更新清单使用 `0.49.0-plus.2`；仓库版本字段仍为上游基线 `0.49.0`，PLUS 身份由发布流水线注入。
- 原会话和原队列不会被迁移或删除。若要继续使用旧队列，需要手动恢复；请勿同时恢复两份相同的待办队列。
- 桌面与 server 使用共享续接逻辑；升级通道仍保持独立。
