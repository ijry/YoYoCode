# YoYoCode v0.48.1-plus.2

自 `v0.48.1-plus.1` 以来的增量版本。主干基于 Codeg 0.48.1，PLUS 版本号由构建期身份注入，git 历史中的版本字段仍与上游一致。

## 本次变化

- **「在新会话中继续」去掉冗余弹窗**：继续流程不再要求用户在弹层里重复选智能体 / 模型 / 提示语；沿用老会话的智能体，新草稿里模型与提示语仍可直接调整，不自动发送。
- **会话轮次上限自动恢复（三态）**：服务端检测到 `session_turn_limit_exceeded`（「当前会话模型已回复 100 轮，达到上限」）后，按设置自动处理：
  - `off`：关闭，不自动处理。
  - `compact`：在**原会话**发送 `/compact`（或该智能体声明的压缩命令），等压缩 turn 结束后**自动发送** `[旧会话](codeg://session/<id>) 请继续上面会话的工作。`；压缩命令不可用、压缩失败或 turn 被取消时自动降级为 `new_session`。
  - `new_session`（默认）：停掉旧会话并标记完成，用**旧会话相同的模型 / 模式配置**开全新会话，自动发送同一条续接提示语。
- **设置入口**：桌面「设置 → 通用」新增下拉「达到会话轮次上限时」，三个选项与 10 种语言文案齐备；`compact` 选项明确标注「未验证」。移动端不改 UI，但通过同一套 HTTP 接口读写同一设置。
- **旧设置迁移**：上一版的布尔开关 `turn_limit_continuation.auto_continue.enabled` 自动迁移为 `true → new_session` / `false → off`，保存新值后旧 key 删除。

## 已知限制

- 仓内压缩保持同一 agent session，**没有机制重置服务商的「会话 100 轮」计数**；因此 `compact` 可能无法真正解决该错误，UI 中已标注未验证。确认无效时请使用 `new_session`。
- 每个会话只自动恢复一次，避免压缩无效时反复压缩 / 续接形成死循环。

## 升级说明

- 构建产物与更新清单使用 `0.48.1-plus.2`（semver 模式），更新器可从 `0.48.1-plus.1` 正常识别到本版。
- PLUS 身份、品牌、更新源与签名密钥沿用既有配置；桌面与 server 两条升级通道互不推送。
- server 默认端口仍为 **18989**；MCode 连接配置码包含访问令牌，请勿分享。
- macOS 安装包沿用 ad-hoc 签名，不做 Apple 公证；server 不发布 macOS 版。

## 验证

- Rust：桌面 / server-bin / mcp-bin `cargo check` 与 `cargo clippy -- -D warnings` 通过；新增设置迁移与提示语单测。
- 前端：新增设置组件与通用设置页定向测试 11/11 通过；新文件通过 Prettier。
- 仓库原有的全量测试 / lint / 构建环境问题（缺失 `src/bin/codeg_server.rs`、过期测试参数、CRLF 与 Prettier 不一致、Turbopack loader 路径越界）与本版改动无关，以 Release workflow 各构建门禁为准。
