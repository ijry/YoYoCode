# YoYoCode v0.45.0-plus.9

修复 ZCode Start Plan 余量摘要在 zcode-acp 0.89+ 桥接下完全不显示的问题。

## 余量摘要修复（0.89.0 桥接兼容）

- zcode-acp-server 0.89.0 起，`account/usage_stats` 里 Start Plan 的 `resetsAt` 从 RFC3339 字符串（0.88.x 的形状）改成了 epoch 毫秒的 JSON **数字**。余量解析器把该字段定为 `Option<String>`，一个字段的类型不匹配让**整包**应答解析失败，归一化结果为空报告，模型弹窗于是静默不渲染余量摘要——请求其实成功了，数据也一直都在。现已让截止时间字段同时接受两种写法（RFC3339 字符串 / epoch 数字，10^12 以下的数字按秒放大），单个字段异常只丢弃该行，不再拖垮整包。
- 按实际在跑的 0.89.0 桥接抓包固化回归用例（ZCODE WEEKEND BUILD，352,540,740/500,000,000，70.5%）；秒级 epoch、非正数、垃圾值等边界一并覆盖。

## 背景

- 用户账号数据本身正常：Start Plan 总量 5 亿 tokens，剩余约 29.5%（≈1.47 亿），与 CLI 直查一致。plus.7 修复的是「瞬态失败钉终身裁决」，本版修复的是「解析成功路径本身的整包脆弱性」（当时评审记账的 M-3）。

## 升级说明

- 构建产物及更新清单使用 `0.45.0-plus.9`；已安装 `0.45.0-plus.7`/`plus.8` 的用户在本版正式发布后可使用内置更新。
- 仓库上游版本基线仍为 `0.45.0`，PLUS 版本号、品牌和更新源由构建期注入。

## 验证

- 账号用量 Rust 测试通过（`--no-default-features --features server-bin --lib account_usage`：0.88.x 字符串形状、0.89+ 数字形状、比例推导、失败/空节丢弃、垃圾输入、秒级缩放与垃圾边界、duplex 假适配器往返）。
