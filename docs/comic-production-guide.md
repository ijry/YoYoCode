# 漫剧创作：从项目到分集与分镜

一个项目目录管理一部整剧。用户通过会话创作、生成分镜及工作台审核编辑，系统负责按统一格式保存分集和镜头；日常使用不需要寻找或编写 JSON。

底层分集保存在 `story/episodes/<episode-id>/`，包含元数据、剧本及分镜。聊天中的创作内容只有经过 MCP 保存或工作台手动保存后，才会成为工作台中的数据；对已有聊天成果可以使用「整理并保存到工作台」。

## 入口

首页「日常办公」的滚动项目首项，以及输入框「+ → Office」，均有「漫剧创作」。它使用内置 `comic-production` expert skill，不依赖 OfficeCLI 安装。

点击入口会准备技能徽标与提示词草稿，并打开活动项目目录的漫剧工作台。它不会自动发送消息、初始化项目或请求媒体生成。如果技能尚未链接到当前代理，入口会引导到 Experts 设置。没有活动项目目录时，先打开一个目录；不要在纯聊天目录里创建漫剧文件。

skill 负责规划与落盘顺序，MCP 负责在当前会话授权的目录里读写，工作台负责查看、修改与审核。它们复用同一份 `story/` 数据，并通过 `comic://changed` 刷新；没有第二套独立数据库副本。

## 推荐起步

打开项目目录并选择「漫剧创作」，发送自然语言要求，例如「创建原创漫剧《雨夜来信》，规划两集并保存剧本，暂不生成素材」。代理负责初始化、分配稳定的分集编号、保存剧本并回读；工作台显示同一份数据。选择一集后，可在本集面板生成分镜草稿，再审核和编辑。

如果左侧此前已经创作完剧本但未保存，使用「整理并保存到工作台」补齐落盘，不需要自己转换格式。具体流程见下节「将会话成果自动保存为分集和分镜」。

## 手动创建与编辑

需要自己控制分集或粘贴已有剧本时，也可以使用表单：

1. 打开项目目录，在工作台选择初始化，填写整剧标题。默认来源是「原创剧本（无小说）」。原创模式不需要上传小说，也不会读取缺失的章节文件。
2. 点击「创建第一集」或「新建分集」，填写标题，可直接粘贴左侧会话已经写好的剧本。
3. 创建后在分集列表选择这一集，进入「剧本」修改并保存。
4. 新建第二集后，可以在同一工作台来回切换。每个分集有独立的剧本草稿和分镜，不需要再建项目。
5. 改编小说时，在项目初始化来源选择中明确选择上传完整小说或外部路径，再检查章节拆分结果。原创和改编走不同的读取流程。

分集 ID 自动从 `ep001`、`ep002` 等分配。标题可以修改，ID 保持稳定。创建时如果另一窗口或代理同时占用了编号，后端会拒绝覆盖，界面重新分配；剧本保存失败时保留输入，重试原本已经创建的分集。

创建项目、登记来源、创建分集和写剧本可能分别失败。界面显示结构化错误中的具体信息，保留草稿，不再把错误对象直接显示成 `[object Object]`。初始化刷新事件不会重新打开一个可重复提交的空闲弹窗。

## 将会话成果自动保存为分集和分镜

推荐按下面的流程操作：

1. 在项目会话里描述整剧和分集要求，代理通过 `comic-production` skill 把规划与剧本保存到工作台。如果此前只在聊天里写了剧本，点击「整理并保存到工作台」：代理会读取已有状态，识别分集并保存剧本，遇到归属不明确或冲突才询问。
2. 在工作台选择对应分集，检查已保存剧本。
3. 点击分镜区的主要按钮「从本集剧本生成分镜」。该点击授权生成文字分镜并直接保存为可审核草稿；代理使用已有 MCP 写入规范化数据并回读，工作台自动刷新。
4. 在工作台审核描述、台词、时长和资源引用，直接编辑镜头。已有分镜的替换仍须确认；图片、视频和配音需要独立操作。

AI 动作针对当前明确选择的分集；不会在其他资源面板悄悄回退到第一集。当前会话必须属于同一项目且支持内置 MCP。剧本未保存或为空时不能生成分镜；有任何分集剧本草稿未保存时，先保存再整理会话成果，避免覆盖本地修改。打开工作台不会自动发起任务，点击动作后才进入当前会话的执行队列。

## 高级迁移：导入分镜 JSON

「更多操作 → 导入分镜 JSON」只用于迁移外部工具导出的数据、恢复已有分镜备份，或接收缺少 MCP 能力的代理产出。普通创作流程不需要这个文件，也不会要求用户自行编写。手动添加镜头仍可直接使用工作台表单。

导入支持一个非空镜头数组，或 `{ "shots": [...] }`。迁移数据的最小示例：

```json
{
  "shots": [
    {
      "id": "shot-0001",
      "description": "雨夜，主角在玄关捡起一封信。",
      "dialogue": [],
      "duration_secs": 3,
      "camera": "static",
      "transition": "cut",
      "refs": { "characters": [], "props": [] }
    },
    {
      "id": "shot-0002",
      "description": "信封特写，日期写着明天。",
      "duration_secs": 2
    }
  ]
}
```

ID 必须是安全、唯一的标识，描述不能为空；可选字段也会校验。缺省时长为 3 秒，显式时长须在 0.1–120 秒内。角色默认服装接受空字符串，省略或 `null` 会规范为同一表示。

镜头按导入数组顺序保存，编辑现有镜头不会按 ID 重新排序。已有分镜时必须确认替换。如果确认期间另一个窗口或代理修改了分镜，后端按确认时的完整快照检查并拒绝覆盖，界面保留导入内容，要求查看最新分镜后重新确认。初始空分镜也有同样的并发检查。

**相同镜头 ID 的已有视频绑定会保留。** 导入前会明确提示这一点。导入新内容后应检查这些视频，必要时在视频审核界面解除绑定，再导出；不能把旧片段自动当成新画面的结果。图片、音频等其他镜头字段按导入内容替换。

## 通过 skill 和 MCP 创作

可以发送这样的请求：

> 在当前目录新建原创漫剧《雨夜来信》，规划两集。确认后先保存第一集剧本和分镜，暂不生成图片、视频或配音。

内置 skill 的主要顺序是：

1. `comic_get_project` 读取状态。空目录只返回 `initialized: false` 与下一工具提示，不写文件。
2. 用户明确要求创建时，调用 `comic_init_project`，标题去除首尾空格后须为 1–200 个字符。
3. 确定原创/改编模式，保存整剧规划和各集元数据。
4. `comic_upsert_episode` → `comic_write_script`，按分集分别保存，再回读。
5. 先创建或复用角色、场景、道具卡片，再保存有序分镜。
6. `comic_get_asset` 和 `comic_get_project` 回读实际内容，报告保存的分集、镜头与资源。
7. 用户明确要求相应媒体操作后，才请求图片、视频、配音或合成；保留审核与绑定步骤。

仅聊天回答「剧本写好了」不代表文件已经保存。若工具缺失，代理应给出可手动粘贴的剧本或分镜 JSON，并明确标记未保存。

升级后的新目录会话可以在尚无 `story/` 时获得漫剧发现与初始化工具，因此同一连接可以完成初始化和后续写入。升级前已经运行的伴生进程不会自动改变工具列表，需要手动重连或新建该目录会话。

Pi、Cline、OpenClaw 当前不能接收这套内置 wire MCP，入口会提供手动工作台和能力提示。其他代理也应检查实际暴露的工具，技能已安装不等于工具已可用。设置 `CODEG_ACP_HOST_TOOLS=agent` 的会话不授予宿主漫剧读写工具；令牌在启动时记录授权，即使伪造请求或之后创建 `story/` 也不会获得额外权限。

所有 MCP 调用绑定会话令牌的工作目录及父连接。模型不能通过 `folderId`、`project_dir` 等额外参数选择其他项目目录。

## 实现与验证记录

核心实现沿用 `StoryStore` 的目录锁、路径约束与原子写入。剧本或分镜写入前补齐分集元数据；旧的缺少 `episode.json` 的合法分集目录可读。UI 的创建、重命名与分镜导入通过可选的 `createOnly`、`expectedMeta`、`expectedStoryboard` 条件保护并发写入；原有无条件 MCP upsert 契约保持兼容，skill 要求编辑前回读、合并已有内容。

最终定向前端回归命令：

```bash
node node_modules/vitest/vitest.mjs run comic \
  src/components/chat/quick-actions.test.tsx \
  src/components/chat/composer/use-composer-shortcuts.test.tsx \
  src/i18n/messages.test.ts
```

主流程调整后的最终结果为 **16 个文件、150 项通过**，涵盖原创来源、分集创建/切换/草稿、自动生成与会话整理入口、保存条件、已有镜头确认、导入解析、并发冲突、视频审核和十语言文案。存在 React `act(...)` 与 Vite 配置提示，未导致失败。21 个改动 TypeScript 文件的 ESLint 通过（仅 CLI 使用 `endOfLine: auto` 适配工作区 CRLF，未修改仓库配置）；TypeScript 无诊断。Next 生产构建静态生成 41/41 项、无动态路由。

Rust 使用临时 target、关闭调试信息和增量编译，避免恢复之前庞大的编译目录：

```bash
cargo test --manifest-path src-tauri/Cargo.toml \
  --no-default-features --features server-bin,mcp-bin,test-utils \
  -j2 --lib --test comic_mcp_e2e --test delegation_e2e_windows \
  --no-run --message-format=json
```

从该次 Cargo JSON 选择新生成的测试程序运行相关过滤器，最终 **55 项通过、0 失败、0 忽略**，包括 store/commands/HTTP、令牌权限、真实 MCP stdio 和两个 Windows 委托集成测试。MCP E2E 确实执行一项，使用真实 FFmpeg 和本地语音服务桩，无付费外部请求。一次编译失败来自新增测试用 `assert_eq!` 比较未实现 `PartialEq` 的错误枚举，改为 `matches!` 后通过；未修改生产错误类型。

浏览器使用实际工作台组件和内存传输桩，已通过真实点击验证原创初始化、创建 `ep001`/`ep002` 并粘贴各自中文剧本、跨集切换恢复第一集未保存草稿、保存后重新启用 AI 分镜动作，以及第二集剧本隔离。分集导航和资源区选中正确，未读取小说；导入弹窗已打开并显示本地化说明。JSON 导入提交和手动镜头编辑未完成浏览器验证，不能记为整链通过；这些路径由上述组件回归覆盖。早期测试浏览器曾暂停 CSS 动画时间线，共享弹窗在生产和开发样式下的独立真实点击对照均正常，关闭后遮罩和滚动锁会移除，未据此修改生产 UI。真实供应商的图像/视频/TTS 请求、完整桌面人工流程及 Mac 实机验收均不在上述通过结果内。
