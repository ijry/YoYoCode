## Context

当前 Tailscale 流程可以使用，但首次配置仍有多次点击和状态死角：登录后还要手动打开授权页、再点启用；Tailscale 已安装但停止时没有连接按钮；DNS 未准备好可能被误导去重新登录。目标是让用户首次安装后，点击一次“开启公网访问”，完成必要的浏览器授权即可获得地址，并同步更新现有 MCode 配置二维码。

保留已完成且未提交的 MCode 二维码改动。本次不自动安装软件、不提权、不执行真实公网发布。

## 推荐交互

- **未安装**：显示官方安装入口和简短说明“仅此电脑需要安装，手机无需安装”。安装返回页面后自动重新检测，保留刷新按钮。
- **已安装**：以“开启公网访问”为主按钮。用户点击后依次完成：必要时启动 Web 服务 → 连接/登录 Tailscale → 开启 Funnel → 确认配置成功。
- **需要授权**：桌面模式自动打开当前操作返回的授权页面，每个地址只自动打开一次。浏览器模式保留明显的“打开授权页面”按钮，避免异步弹窗被拦截；两种模式均可复制链接。
- **授权完成**：自动继续下一步，不要求再点一次启用。成功后仍自动选中公网地址、更新访问地址列表和 MCode 配置二维码。
- **异常**：区分服务未启动、Tailscale 未连接、设备待管理员批准、DNS 未准备好、权限不足和端口配置冲突。提供明确的下一步，不反复自动登录或重试。
- 保留取消、关闭公网访问和手动刷新。用户取消或停止 Web 服务后，停止后续自动操作。

## 实现步骤

### 1. 补足后端前置条件信息

修改 `src-tauri/src/web/tailscale_funnel.rs`、对应测试和 `src/lib/api.ts`。

- 在现有状态 DTO 中增加可选的前置条件字段，区分连接 Tailscale、账号登录、设备审批、DNS 设置及启动 Web 服务，兼容旧后端缺失该字段的情况。
- 复用 `login_core` 的 `tailscale up` 能力处理已停止的当前账号；不切换 profile。
- 修正 Running 但缺少有效 DNS 时的错误归类，避免登录死循环。
- 继续使用已有状态、登录、启用、取消接口，不新增下载器或安装器。

### 2. 将多个动作串成一次明确的开启操作

修改 `src/components/settings/tailscale-funnel-settings.tsx` 和 `web-service-settings.tsx`。

- 父组件复用现有 Web 服务启动逻辑，向 Funnel 区域提供当前运行状态及可等待结果的启动回调；启动失败时不继续发布。
- Funnel 组件保存本次用户明确发起的开启意图，按状态推进，每个阶段只提交一次请求。
- 复用现有轮询、请求版本和取消机制。页面卸载、用户取消、手动停止服务或操作失败后，不让过期响应触发下一步。
- 授权链接通过现有 `src/lib/platform.ts::openUrl` 打开；仅当前用户发起的流程自动打开，不因普通状态刷新或历史链接反复打开。
- 超时仍可手动打开/复制授权链接并重试，错误状态不无限自动重试。

### 3. 提示和文档

在十种 `src/i18n/messages/*.json` 中更新状态、主按钮与下一步提示，界面避免要求普通用户理解 CLI、node attribute 等细节。更新 `docs/tailscale-funnel.md` 的首次使用流程。
