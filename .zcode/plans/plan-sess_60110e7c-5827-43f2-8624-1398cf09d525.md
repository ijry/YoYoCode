# 手动停止后扣住消息队列（hold），恢复手动控制

## Context

当前行为：用户手动停止回合后，`complete_attempt` 把 `cancelled` 映射回 `"open"`，drain worker 立即发出队列里下一条消息——前一个任务还没做完，第二个任务就发出去了。目标：**手动停止被记录为用户操作，队列扣住不自动发**；队列行提供"立即发送"按钮由用户主动选择；此状态下输入框消息**直接发送到会话**（优先于队列，不追加）。解除时机（用户已确认）：**下一个回合正常完成即自动恢复**，横幅另提供"恢复自动发送"按钮。自动取消（automation/work_task/CLI）不触发 hold。

## 后端（src-tauri/src/）

### 1. 记录"用户手动停止"
- `ConnectionCommand::Cancel` 携带 `by_user: bool`（`acp/manager.rs:2218` `ConnectionManager::cancel` 加参数）。用户入口 `commands/acp.rs:12246`（acp_cancel）与 `web/handlers/acp.rs:461` 传 `true`；automation/engine.rs:985、work_task/engine.rs:973,2590、cli_run/service.rs:2471 传 `false`。
- connection.rs 的 mid-turn cancel 分支（~15740）把 `by_user` 记到 `SessionState` 新字段（如 `cancel_by_user`）。
- `SessionState::capture_queue_completion`（`acp/session_state.rs:843-862`）捕获 `TurnComplete{stop_reason:"cancelled"}` 时结合该标志，在 `QueueTurnCompletion`（`db/service/message_queue_control_service.rs:30-36`）上加 `user_cancelled: bool`，随后消费/复位标志。

### 2. hold 状态（新列，不改 status 语义）
- 新迁移：`ALTER TABLE message_queue_state ADD COLUMN hold TEXT`（仿 `db/migration/m20261106_000002_message_queue_pause.rs` 风格；表无 CHECK 约束，安全）。
- `MessageQueueState` 结构体（control_service.rs:13-20）加 `hold: Option<String>`，随 `MESSAGE_QUEUE_STATE_EVENT` 序列化到前端；`state_on` SELECT 同步。
- `complete_attempt`（:124-169）：
  - `user_cancelled && !recovery_of` 且队列仍有 pending 项 → status 照旧写 `"open"`，同时 `hold = 'manual_stop'`（pending 判定仿 `pending_owners` 查询）。
  - `success` → 清除 hold（`hold = NULL`）。其余结果不动 hold。
- `can_drain`（:74-77）加 `AND hold IS NULL` —— drain 的 `claim_next` 内部复查（`message_queue_service.rs:197-200`）与 `try_drain_owner`（drain.rs:293）自动生效，无需改 drain 逻辑。
- `begin_attempt` 的 upsert（:111-115）UPDATE 列表不含 hold → 自然保留，确认 INSERT 列表补默认 NULL。
- 复用：`send_queued_prompt`（manager.rs:1343）、`claim/mark_sending/acknowledge/release`（message_queue_service.rs）。

### 3. 两个新命令（照 `message_queue_continue` 的四件套模板：Tauri 命令 + HTTP handler + router + lib.rs 注册）
- `message_queue_release_hold(owner_id)`：CAS `hold IS NOT NULL → NULL`，bump revision，广播 state 事件，`drain.notify`。
- `message_queue_send_now(owner_id, item_id)`：校验 status 允许（open/hold）且无 active attempt、行 pending → 定向 claim（仿 claim_next 的 token 事务）→ `mark_sending` → `manager.send_queued_prompt` → 成功 `acknowledge`，失败 `release` 并返回错误。不走 drain，立即开始该行回合；回合成功完成后由 complete_attempt 自动清 hold。

### 4. Rust 测试
- control tests：user-cancel+有 pending → hold 置位且 can_drain=false；success → hold 清；cancel 时队列空 → 不置 hold；release_hold 生效。现有 `an_ordinary_user_cancel_is_not_reported_as_an_execution_error`（message_queue_control_tests.rs:118-128）保持通过（status 仍 open），补 hold 断言。
- drain tests：held owner 不被 drain，release 后恢复。
- session_state capture 测试：by_user 标志传递。
