## Context

审查报告 `docs/comic-workflow-review-2026-11-11.md` 已完成。当前主要风险是旧分镜/资源快照覆盖后台更新、异步保存清除新草稿，以及部分媒体路径无法导出。第一阶段先让现有普通工作台可靠，再为后续普通／画布双视图提供安全基础。

**本次范围：R01–R07，加上与保存直接相关的 R09。** 不新增画布、自由工作流编排、资源创建、预算、任务历史或批量操作；不迁移数据库，不调用付费供应商，不提交、推送或发布。

## 1. 将后台分镜更新改为锁内业务操作

在 `src-tauri/src/comic/store.rs` 增加候选状态和图片绑定的限定字段更新方法，复用 `write_guard`、`write_storyboard_locked` 及现有音频／视频绑定模式。

- 同一写锁内读取最新分镜，只修改目标镜头的相关字段。
- 候选完成仅把当前 `Prompted/Generating` 改为 `Candidate`，不得将已选用状态降级。
- 图片绑定只改变 `selected/state`，保留台词、引用、音频、视频及排序，返回实际写入的分镜。
- `src-tauri/src/comic/task.rs` 的 `mark_candidate`、`bind_candidate` 改用上述方法，保留候选历史和已有路径校验规则。
- 同一图片字段仍遵循最后取得锁的显式绑定生效；视频继续保留现有 CAS 确认。

此保证适用于本进程经 StoryStore 写入的操作，不宣称具备跨进程文件事务。

## 2. 分离普通编辑与全量 upsert

增加两条明确的工作台编辑接口：`comic_update_shot_fields`、`comic_update_asset_text`，不增加 MCP 工具，也不改变旧 upsert 或整集导入语义。

- 镜头允许编辑描述、对白、时长、镜头参数和资源引用；禁止修改 `no/state/selected/audio/video`。
- 资源只编辑名称、描述和提示词片段；保留最新 `seed/personality/turnaround/outfits/expressions/refs`。
- 前端根据编辑基线只提交实际改变字段；资源引用按子字段更新。请求明确区分“省略保留”与“显式 null/空数组清空”，不直接使用带默认值的完整文档模型作补丁。
- 后端在现有锁内合并最新文档，复用 `validate_shot_refs` 验证修改后的引用。目标已删除时拒绝，不偷偷重建。
- 对本次修改字段比较编辑基线；同字段已被他人修改时返回明确冲突并保留草稿。仅素材变化不阻止普通文本保存。
- 新建镜头继续走原 upsert；MCP 完整创建／替换、素材维护、导入快照检查、视频保护及返回格式保持不变。

关键文件：`src-tauri/src/comic/model.rs`、`store.rs`、`commands/comic.rs`、`web/handlers/comic.rs`、`web/router.rs`、`lib.rs`，以及 `src/lib/comic.ts`。桌面注册和 Web 路由同时接入共享 core；如需新增冲突提示，同步十语言消息。

## 3. 前端只清除成功提交的那份草稿

修改 `src/components/comic/comic-workbench-panel.tsx` 的 `ShotEditDialog` 和 `AssetPanel`，小范围调整 `src/stores/comic-store.ts` 的编辑基线类型。

- 提交前捕获草稿对象，成功后复用 `clearResourceDraft(folderId, key, submittedDraft)`；不再清除完成时的当前草稿。
- 保存期间继续输入或打开其他镜头，旧请求完成不得关闭或清除新编辑。
- 失败或冲突保留草稿；视频解绑只刷新绑定，不把未保存文本当作已保存并清掉。
- 资源保存使用后端合并后的文档，不再从旧卡片拼出“最新结果”；相关读取使用现有最新请求标识模式避免旧响应覆盖。
- 保留项目／分集隔离和卸载后的草稿恢复，不做全面 store 重构，不顺带新增 seed 控件。

## 4. 修复纯视频合成及输入快照

修改 `src-tauri/src/comic/compose.rs`、`compose_task.rs`。

- 合成计划的图片输入允许为空；旧计划 JSON 中的图片字符串仍可读取。
- 有已绑定视频的镜头以视频为画面来源，不要求、复制或解码被替代的定稿图；没有视频的镜头仍必须有有效图片。
- 输入冻结、排队恢复和渲染同步调整，保留路径限制、文件大小限制、镜头顺序、字幕及现有音频优先规则。
- 不在这一步顺带改变短视频延长策略；验证时检测视频流与音频流时长，不仅检查容器时长，并如实报告剩余差距。

## 5. 补齐媒体工具与模型列表契约

- `Dockerfile`、`Dockerfile.ci` 安装 FFmpeg/FFprobe。
- 复用现有进程执行和 `unavailable` 错误模式，增加小范围工具预检：TTS/视频在供应商调用前检查所需工具；合成在输入快照和任务入队前检查。图片生成不因不需要的媒体工具而被阻断。
- 缺依赖明确拒绝，不先产生收费调用再失败。测试用可控制的预检结果，不通过全局修改 PATH 制造竞争。
- 模型列表保留客户端现有平铺 camelCase 参数：Tauri 包装接收对应独立参数后组装 `ListProviderModelsParams`；Web 直接反序列化该结构，移除重复的 `kind + flatten`。
- 复用 `comic_list_provider_models_core`，验证真实请求形状与 HTTP mock 查询，不只 mock 前端 `comicApi`。

## 6. 回归与验收

按测试先行逐项修复，先看到新增回归失败，再实现并重跑：

1. 后台候选完成与编辑、选图、配音、排序交错时，互不撤销；迟到完成不能降级已选用镜头。
2. 旧资源／镜头草稿保存保留最新素材和角色种子；无关字段不回写，同字段冲突不丢草稿。
3. deferred-save 测试覆盖保存后继续输入、切换镜头、失败重试及解绑不清文本。
4. 旧 MCP 全量写入、显式清空、视频 CAS、JSON 导入、引用校验和候选历史保持兼容。
5. 纯视频、图片加配音、图／视频混合合成成功；删除未使用定稿图不阻断视频导出；无有效画面来源仍拒绝。
6. 旧合成计划可反序列化，排队快照不依赖后续修改的原素材。
7. 桌面参数形状与 Web 反序列化通过；工具缺失时供应商请求次数为零。
